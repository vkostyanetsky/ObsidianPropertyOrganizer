# Property Organizer

Плагин для Obsidian, поддерживающий заданный вами порядок свойств в YAML frontmatter. Вы описываете порядок для папки, а плагин приводит к нему свойства подходящих заметок — значения, имена свойств и содержимое заметки остаются неизменными.

Сортировка выполняется вручную — двумя командами, — а также, если включить соответствующую настройку, один раз при открытии хранилища. Заметки не сортируются автоматически при создании, изменении, переименовании или перемещении.

## Пример

Шаблон для папки `Projects`:

```text
type, status, created, modified, tags
```

До:

```yaml
---
tags:
  - work
created: 2026-08-03
summary: Quarterly report
type: project
status: active
---
```

После:

```yaml
---
type: project
status: active
created: 2026-08-03
tags:
  - work
summary: Quarterly report
---
```

`type`, `status` и `created` переместились в начало в порядке шаблона. Свойства `modified` в заметке нет, поэтому оно игнорируется — если только не включена настройка **Create missing properties**. `tags` перечислено в шаблоне и поднимается выше; `summary` не перечислено и остаётся после упорядоченных свойств.

## Сопоставление папок

- Шаблон применяется ко всем Markdown-заметкам, лежащим непосредственно в его папке **и в любой её подпапке**. Шаблон для `Projects` действует и для `Projects/note.md`, и для `Projects/Test/note.md`.
- Сравнение учитывает границы сегментов пути: `Projects` **не** соответствует `Projects-old/note.md`.
- Пустой путь означает корень хранилища, равен `/` и соответствует всем Markdown-заметкам. Такой шаблон удобно использовать как общий fallback.
- Пути нормализуются средствами Obsidian, поэтому `/Projects/`, `Projects` и `Projects//` — одна и та же папка.
- Заметки, которым не соответствует ни один шаблон, не обрабатываются.

## Приоритет шаблонов

Шаблоны проверяются сверху вниз, и **используется первый подходящий**. Более поздние шаблоны к этой заметке не применяются. Размещайте более специфичные папки выше общих:

| № | Папка | Свойства |
|---|-------|----------|
| 1 | `Projects/Archive` | `type, archived, created` |
| 2 | `Projects` | `type, status, created` |
| 3 | *(пусто)* | `created, tags` |

С таким списком `Projects/Archive/note.md` обрабатывается только первым шаблоном, `Projects/note.md` — вторым, а всё остальное — третьим.

## Списки свойств

Имена свойств задаются списком через запятую, в требуемом порядке:

```text
type, status, created, modified, tags
```

- Пробелы в начале и конце имени удаляются.
- Пустые элементы игнорируются, поэтому запись `type,, status,` допустима.
- При повторении имени учитывается только первое вхождение.
- Имена регистрозависимы и не изменяются: `Type` и `type` — разные свойства.

### Подсказки имён

При вводе списка свойств поле подсказывает имена свойств, которые уже используются в хранилище, — так же, как это делает Obsidian при добавлении нового свойства в заметку:

- Список подсказок сужается по мере ввода, а варианты упорядочены по тому, насколько они соответствуют введённому.
- Вариант выбирается мышью либо стрелками и клавишей `Enter`; клавиша `Esc` закрывает список.
- Выбор варианта подставляет полное имя свойства вместо набранного текста.
- Подсказки относятся к тому свойству, в котором находится курсор, независимо от его места в списке: имя, вводимое после запятой, дополняется так же, как первое.
- Имена, уже перечисленные в этом же поле, повторно не предлагаются: повторение имени всё равно не влияет на порядок.
- Принимать подсказку не обязательно: свойство, которого в хранилище ещё нет, просто вводится вручную.

Имена берутся из frontmatter заметок, находящихся в кэше метаданных Obsidian, поэтому заметки с диска не читаются, а подсказки следуют за изменениями хранилища.

## Правила сортировки

- Свойства, перечисленные в выбранном шаблоне, располагаются в начале в заданном порядке.
- Все остальные существующие свойства идут после них с сохранением исходного относительного порядка — если только они не удаляются настройкой **Unlisted properties**.
- Значения, имена свойств и их регистр не изменяются.
- Содержимое заметки после frontmatter не затрагивается.
- Если frontmatter уже в требуемом порядке, файл повторно не записывается.
- Если у заметки нет frontmatter и настройка **Create missing properties** отключена, ничего не происходит.

Frontmatter переписывается штатным API Obsidian, поэтому форматирование YAML (отступы, кавычки, комментарии) может быть нормализовано. Значения свойств при этом сохраняются.

## Create missing properties

Глобальная настройка, по умолчанию **отключена**.

- **Отключена** — сортируются только свойства, уже существующие в заметке. Отсутствующие свойства шаблона игнорируются.
- **Включена** — все свойства выбранного шаблона, которых нет в заметке, создаются пустыми:

  ```yaml
  property:
  ```

  После создания применяется требуемый порядок.

Типы свойств остаются на усмотрение Obsidian: плагин не назначает и не изменяет тип свойства. Если для имени уже назначен тип на уровне хранилища, Obsidian применит его самостоятельно.

## Unlisted properties

Глобальная настройка, определяющая, что делать со свойствами frontmatter, которые **не** перечислены в подошедшем заметке шаблоне. Действует и для обеих команд, и для автоматического запуска, и только для заметок, которым подошёл шаблон: заметки без шаблона не изменяются.

| Значение | Что происходит |
|----------|----------------|
| **Keep all** *(по умолчанию)* | Ничего не удаляется. Неперечисленные свойства идут после перечисленных с сохранением относительного порядка. |
| **Remove if empty** | Неперечисленные свойства с пустым значением удаляются; заполненные остаются и идут после перечисленных. |
| **Remove all** | Удаляются все неперечисленные свойства. После обработки во frontmatter остаются только свойства шаблона. |

Пустыми считаются значения:

- свойство Obsidian без значения (`null`);
- пустая строка или строка из одних пробелов;
- пустой массив;
- пустой объект.

`false`, `0` и даты — это значения, а не пустые свойства.

Свойства, **перечисленные** в шаблоне, не удаляются никогда, даже если они пустые.

Для заметки, которой подошёл шаблон, порядок действий такой:

1. Шаблон выбирается по обычным правилам сопоставления папок.
2. Свойства, отсутствующие в шаблоне, обрабатываются согласно настройке **Unlisted properties**.
3. Отсутствующие свойства шаблона создаются, если включена настройка **Create missing properties**.
4. Оставшиеся свойства сортируются в порядке шаблона.

Удаление свойств необратимо, поэтому не меняйте значение по умолчанию, пока не убедитесь, что шаблоны перечисляют все нужные свойства: fallback-шаблон для корня хранилища с пустым списком свойств вместе с **Remove all** очистит frontmatter всех заметок.

## Команды

| Команда | Что делает |
|---------|------------|
| **Sort properties in all notes** | Обрабатывает все Markdown-заметки, которым соответствует хотя бы один шаблон. Заметки вне настроенных папок не обрабатываются. Показывает итог: `3 notes updated, 12 unchanged, 40 skipped, 0 errors.` |
| **Sort properties in current note** | Обрабатывает только заметку текущего активного Markdown-представления. Если активный вид не является Markdown-заметкой, команда недоступна. |

В итоговом сообщении *skipped* — это заметки, которые не обрабатывались вовсе: им не подошёл ни один шаблон либо у них нет frontmatter при отключённой настройке **Create missing properties**.

Команда для текущей заметки сообщает результат:

- `No matching template for the current note.`
- `Properties are already organized.`
- `Properties sorted.`

## Process all notes on vault startup

Глобальная настройка, по умолчанию **отключена**: заметки обрабатываются только по команде.

- **Отключена** — при открытии хранилища ничего не происходит.
- **Включена** — после завершения загрузки хранилища обрабатываются все Markdown-заметки, которым подошёл шаблон.

Команды работают одинаково при любом значении настройки: её отключение их не выключает.

Настройка считывается при загрузке хранилища, поэтому её включение вступает в силу при следующем открытии. Чтобы обработать хранилище сразу, воспользуйтесь командой **Sort properties in all notes**.

## Автоматический запуск

Если настройка **Process all notes on vault startup** включена, автоматическая сортировка выполняется **ровно один раз за загрузку хранилища**: после готовности рабочего пространства и после завершения первоначального формирования кэша метаданных, не блокируя загрузку интерфейса. Изменения файлов, сделанные самим плагином, повторный запуск не вызывают.

Включение, отключение или hot reload плагина после завершения загрузки хранилища **не** запускают пакетную сортировку — используйте команды.

После автоматического запуска Notice показывается только если были изменены файлы или возникли ошибки.

## Настройки

- **Process all notes on vault startup** — описана выше. По умолчанию отключена.
- **Create missing properties** — описана выше.
- **Unlisted properties** — описана выше. Выпадающий список со значениями **Keep all**, **Remove if empty** и **Remove all**.
- **Folder templates** — упорядоченный список. В каждой строке: поле папки с подсказками папок хранилища и список свойств через запятую с подсказками имён свойств, используемых в хранилище. Порядок строк и удаление управляются элементами, которые Obsidian рисует для списка, а кнопка **Add template** добавляет новую строку. Изменения сохраняются автоматически.

Настройки описаны декларативно, поэтому находятся поиском в разделе *Settings*.

## Установка

Плагин требует Obsidian **1.13.0** или новее: именно в этой версии появился декларативный API настроек, на котором он построен.

Плагин опубликован в каталоге сообщества, поэтому обычный способ установки — прямо из Obsidian:

1. Откройте *Settings → Community plugins → Browse*.
2. Найдите **Property Organizer**.
3. Установите плагин и включите его.

### Установка вручную

1. Соберите плагин (см. ниже) либо скачайте `main.js`, `manifest.json` и `styles.css` из релиза.
2. Скопируйте эти три файла в `<хранилище>/.obsidian/plugins/property-organizer/`.
3. Перезапустите Obsidian и включите **Property Organizer** в разделе *Settings → Community plugins*.

## Ограничения

- Заметки обрабатываются только по команде — либо один раз за загрузку хранилища, если включена настройка **Process all notes on vault startup**; сортировки «на лету» при создании, изменении, переименовании и перемещении нет.
- Заметка с некорректным YAML пропускается, учитывается как ошибка и выводится в консоль разработчика. Обработка остальных заметок продолжается.
- При перезаписи заметки форматирование YAML может быть нормализовано Obsidian; сохранение комментариев внутри frontmatter не гарантируется.
- Пути папок сравниваются с учётом регистра.
- Типы свойств не создаются и не изменяются.

## Мобильная версия

Плагин не является desktop-only и работает на мобильных устройствах. Используется только публичный API Obsidian — без Node.js, Electron и прямого доступа к файловой системе, — а заметки обрабатываются последовательно, одна за другой, чтобы большое хранилище не порождало массу параллельных записей. Элементы управления списком шаблонов папок — добавление, удаление и изменение порядка — те же, что Obsidian рисует для любого списка настроек, поэтому ведут себя как везде в приложении; кнопка добавления, например, на десктопе выглядит кнопкой, а на мобильных — строкой. Плагин отрисовывает только два поля внутри строки.
